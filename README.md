# CaeRogue

CaeRogue 是一款原生 HTML / CSS / JavaScript 构建的浅色卡牌战术单页应用。它包含同屏双人、人机对战、新手教程、肉鸽、挑战、无尽、卡牌库、牌组构筑、统一卡牌编辑器、扩展包与创意工坊。项目没有构建步骤、第三方依赖、外部字体或远程接口；美术、图标与纸张纹理全部来自 `assets/`。

## 运行

必须通过本地 HTTP 服务打开。卡牌、默认牌组和语言文件会在启动时通过 `fetch` 读取，`file://` 直接双击无法加载这些数据。

```bash
cd /storage/emulated/0/vibec/projects/CaeRogue
python3 -m http.server 8765 --bind 0.0.0.0
```

访问 `http://<本机局域网地址>:8765/index.html`。首次启动会创建教程入口；完成教学对战后，首页主按钮会从「开启面对面对战」切换为「肉鸽模式」。

所有玩家数据保存在浏览器 `localStorage` 的 `caerogue.state.v1` 中。默认卡牌与默认牌组内容从 `data/` 读取，独立牌组构筑结果会写入本地存档。

## 数据文件

```
data/pack/defaultcards.json   默认卡包（角色、技能、效果、装备、符文）
data/pack/index.json          data/pack 扩展包清单
data/pack/extra_supplies.json 随项目提供的示例扩展「旅途补给」
data/deck/default_a.json      红方默认牌组（默认：普通的史莱姆）
data/deck/default_b.json      蓝方默认牌组（默认：普通的史莱姆）
data/rogue/config.json        肉鸽规则、地图、遭遇、商店、战利品与休整配置
data/rogue/events.json        肉鸽事件与选项效果
data/lan/zh_cn.json           简体中文界面文案
data/lan/en_us.json           英文界面文案
```

新增本地扩展时，把扩展包 JSON 放进 `data/pack/`，再把文件名加入 `index.json` 的 `packs` 数组。启动时会读取并启用这些文件；同 ID 的本地文件扩展会在每次启动时更新。默认卡包不放入清单，它始终以 `defaultcards.json` 为准。

`index.json` 必须是合法 JSON，多个文件名之间要用英文逗号分隔。索引格式错误时，启动会提示扩展包索引读取失败，并继续以其余可用内容运行，而不是静默忽略。

扩展包格式：

```json
{
  "format": "caerogue.expansion",
  "id": "demo.frost",
  "name": "霜与诗",
  "version": "0.1.0",
  "author": "本地作者",
  "description": "扩展说明",
  "dependencies": ["core"],
  "countDefs": { "frost": "霜痕" },
  "content": {
    "units": [],
    "skills": [],
    "effects": [],
    "equipment": [],
    "runes": []
  }
}
```

角色、技能、装备和符文使用全局唯一 ID；扩展内容建议使用自己的包命名空间。导入时会检查格式、ID 冲突、依赖与引用完整性。

## 已实现功能

### 对战

- **新手教程**：四步说明与一场入门对战。完成教程后首页主按钮变为「肉鸽模式」；普通面对面对战仍可从主菜单进入。
- **面对面对战**：同屏双人，双方分别显示为红方 / 蓝方，蓝方先手；强制使用公共牌池抽牌模式，不进行牌组构筑。
- **自定义对战**：可开启或关闭战斗中抽牌。开启时双方从公共单位牌池抽牌、初始无登场角色；关闭时读取牌组构筑模块保存的红蓝独立牌组，未修改时默认牌组为双方各一只史莱姆。
- **规则配置**：初始抽牌、重复角色、退场回牌堆、战斗中补充抽牌、场地上限。
- **自动对手**：肉鸽、挑战、无尽和自定义人机对战的对手由本地自动决策器控制。
- **手动补牌**：点击场地空缺位置，从手牌选择角色补入；自动控制方自行补牌。
- **「区」**：被击败时召唤两个不受场地上限限制的「区」；轮到它时强制随机选择对方目标自动攻击。

### 装备与符文

- 战斗界面提供独立的「装备与符文」整备栏。单人模式显示一栏；同屏双人显示「红方装备与符文」与「蓝方装备与符文」两栏。
- **只能在该方行动时调整**装备、卸下装备和符文。非当前行动方的整备栏锁定。
- 装备默认未穿戴，可选择目标角色穿戴或销毁；角色装备栏中可单独卸下武器 / 饰品。
- 每方最多启用三张符文；符文对该方全体单位生效。
- 获取路径：卡牌库与牌组构筑、肉鸽商店、休整节点（翻找旧装备 / 临摹符文）、战斗奖励与无尽奖励。商店会保证出现当前可购买的装备或符文。

### 战斗反馈

- Canvas 飞弹、拖尾、命中爆炸、治疗与辅助光环、召唤分裂、退场红环和伤害跳字。
- 先播放动画，再更新生命、退场、召唤和日志。伤害命中时立即预览生命条变化；致命伤害会预览生命归零、红色退场状态，动画结束后再替换为分裂/退场结果。
- 技能、效果、召唤与致命保护都有对应的离散动画；伤害、治疗、后续附加伤害按命中顺序排队。
- 附加伤害在主伤害命中之后单独结算，不会抢在主伤害之前。
- 被动触发、计数变化、增益/减益也至少播放一次技能脉冲或效果光环。
- 角色卡显示伤害提升值、伤害提升百分比、最终伤害、治疗、抗性、受伤修正等当前基础数值；单位档案同时显示基础攻击/抗性与当前数值。
- 支持「减少动效」；开启后直接提交界面状态。

### 内容与工具

- **卡牌库**：按类型、品质与关键词筛选；查看卡牌属性、技能描述与流程。
- **牌组构筑**：独立模块，从首页「牌组构筑」进入；管理红蓝双方牌组，供挑战等读取。对战配置页不再嵌入牌组构筑。
- **编辑器**：统一创建和编辑角色、技能、效果、装备、符文。可以切换目标包，直接编辑默认卡包、草稿或任意已加载扩展；草稿作为独立包即时可用，发布后会清空。支持修改包 ID / 卡牌 ID 并同步前缀与引用。
  - 角色：名称、品质颜色、系列 / 特性、生命、攻击、抗性、生命上限限制、计数、自动行动、介绍、卡面与持有技能。
  - 技能 / 效果：触发、条件、目标、变量、分支、循环、召唤、强制退场、属性修改与步骤排序。
  - 装备：武器 / 饰品、数值修正、赋予技能、介绍与卡面。
  - 符文：适用系列、数值修正、赋予技能、介绍与卡面。
- **编辑入口收拢**：角色创建已从卡牌库移除；卡牌库只负责浏览，牌组构筑只负责调整卡组，所有卡牌创建 / 编辑都在编辑器内完成。
- **扩展包管理**：JSON / CAE1 分享码导入、启用、禁用、内容查看；支持同时导出 JSON 并复制分享码。
- **创意工坊**：本地扩展索引、分享码导入导出、收藏、说明、发布编辑器草稿。
- **肉鸽 / 无尽编队**：战斗前打开「编队与整备」，从本局角色池中选择 1–3 名出战角色，且至少 1 名计数角色。未选择的角色不会进入本场战斗；战斗不再自动读取整副牌组出战。
- **肉鸽**：以 30 金币起步，不再提供初始自选队伍；常驻角色商店、节点地图、战斗、精英、商店、事件、休整、首领、战利品三选一、资源与强化保留。
- **挑战 / 无尽**：预设连续战斗、自定义挑战设计器与逐层提升的随机对手；无尽以 30 金币起步，可在每层战斗前调整编队。
- **常驻角色商店**：非节点商店，5 张角色卡，白 50% / 蓝 40% / 金 10%，价格 5 / 10 / 15 金币，手动刷新 10 金币；每完成一个节点自动免费刷新一次。商店角色可点击预览。
- **卡牌预览**：商店中的角色/装备/符文、战斗双方的角色头像与名称、已装备的装备与符文、编队装备等都可点击打开详情预览。
- **最后一个计数单位警告**：释放会使目标所在方最后一个计数单位变为不计数的技能前，会弹出确认警告；取消则不会释放。
- **设置**：减少动效、紧凑日志、危险操作确认、伤害公式显示、AI 节奏、界面语言、本地存档维护。

## 战斗结算顺序

界面把「结算」与「呈现」分开：

1. 玩家确认行动后，同步战斗引擎立即得出最终结果。
2. Canvas 播放本次行动的全部飞弹、命中、爆炸、光环、召唤与脉冲。
3. 伤害命中时用预览方式更新目标生命条；此时日志与最终场面仍保持行动前状态。
4. 所有离散动画结束后，再提交新的生命值、退场、召唤、回合状态与日志。
5. 动画期间战斗交互锁定，避免重复操作。

持续光环、初始入场与静态数值不产生独立的离散结算动画。装备/符文调整属于整备操作，不消耗行动，也不需要战斗动画。

## 数据模型

角色、技能、高级效果、装备和符文都按 ID 独立存储。角色引用技能、装备和符文。

```js
// 角色
{
  id: 'catgirl_jk', packId: 'core', name: '一般猫娘(jk)',
  quality: 'blue', counted: true,
  hp: 9, attack: 2,
  resistance: { type: 'general', value: 1 },
  skills: ['cat_sweep', 'cat_burst'],
  faction: 'sakura' // 系列/特性，仅用于符文匹配，不表示卡牌归属
}

// 技能
{
  id: 'cat_burst', packId: 'core', name: '樱落斩',
  type: 'active', op: 'attack',
  trigger: { event: 'manual' },
  requirements: [{ scope: 'unit', countId: 'sakurafade', op: 'gte', value: '3' }],
  targetMode: 'enemy',
  steps: [
    { kind: 'damage', target: 'chosen', damageType: 'physical', formula: '4' },
    { kind: 'modifyCount', scope: 'unit', countId: 'sakurafade', mode: 'add', formula: '-3' }
  ]
}

// 高级效果
{
  id: 'undying', packId: 'core', name: '不死诅咒',
  type: 'special', removable: false, stackable: false,
  mods: { finalDmgPct: -99999 },
  trigger: { event: 'fatalDamage' },
  steps: [
    { kind: 'immuneDamage' },
    { kind: 'heal', target: 'self', formula: '$hpMax - $hp' }
  ]
}
```

角色的 `faction` 是**系列 / 特性**，只用于匹配适用系列相同的符文，不限制卡牌加入哪一方牌组。战斗中的一方计数保存在各自一方的 `side.counts` 中，不按卡牌系列跨方共享。

### 计数与变量

- 全场计数：整场战斗共享。
- 一方计数：战斗双方各自保存；即使双方场上有同系列角色，计数也互不共享。
- 角色计数：每个上阵单位独立记录，同名角色互不影响。
- 效果层数：挂在对应战斗单位的独立效果实例上。

### 目标选择器

目标字段使用花括号标识符：

```text
{target}                     技能指定的目标
{enemy}                      全体敌方
{friendly}                   全体友方
{self}                       自己
{with_effect[love]}          全体持有 love 效果者
{satisfy({target}, 条件)}    集合中满足条件的对象，条件内 {unit} 为当前对象
{unit}                       遍历中的当前对象
{enemyside}                  敌方阵营，只能读取计数
{friendlyside}               友方阵营，只能读取计数
{field}                      战场，只能读取计数
```

集合运算：

```text
in({}, {})      交集
un({}, {})      并集
diff({}, {})    相对差集
```

攻击对象：

```text
choose({enemy}, 1)    从集合中选择至多 1 个单位
choose({enemy}, 3)    从集合中选择至多 3 个单位
all({enemy})          自动选中集合中的所有单位
```

### 数值表达式

```text
{target}.atk
{target}.hp
{target}.max_hp
{target}.res
{target}.last_hit_count
{target}.count                  目标数量
{target}.effect[love].count     指定效果层数
{target}.count[ha]              对象计数
{enemyside}.count[ha]           敌方阵营计数
{friendlyside}.count[ha]        友方阵营计数
{field}.count[ha]               战场计数
```

支持：

- `+ - * /`、括号和一元正负号
- `log(,)`、`min()`、`max()`、`floor()`、`ceil()`、`round()`、`abs()`、`sqrt()`、`pow(,)`
- 常数 `\pi`、`\e`
- 字符串 `[id]`
- 条件：`==`、`!=`、`<=`、`>=`、`<`、`>`，以及 `and`、`or`、`not`
- 非法对数、除零或非有限结果按 0 处理

### 旧版兼容与迁移

旧版目标 `chosen / self / allEnemies / allAllies / item / owner` 与旧版 `$atk`、`$target.hp` 等公式仍由兼容解析器运行。编辑器提供「迁移新版表达式」一键转换当前包；未识别的旧变量会保留并由兼容解析器继续处理。

### 步骤级旧版 / 公式模式

每个步骤块独立选择「旧版」或「公式」：

- 旧版：目标使用下拉选择器，条件步骤使用左侧/运算符/右侧三段式。
- 公式：目标使用 `{...}` / `choose` / `all` 表达式，条件步骤使用单一条件表达式。
- 两种模式的原字段都会保留，来回切换不会丢失另一套写法。
- 新建步骤默认使用公式模式；旧步骤默认按旧版模式显示。

### 仅保留解析的旧步骤

以下步骤已从步骤选择器中移除，旧卡牌中的实例仍可被引擎解析，但编辑器不再允许创建或编辑：

- `selectTarget`：直接使用目标表达式替代。
- `readCount`：直接使用 `{self}.count[id]`、`{friendlyside}.count[id]` 等公式替代。
- `setVar`：直接在使用处内联公式替代。

旧实例在编辑器里只显示兼容占位块，可删除；运行时不丢失原逻辑。

### 其他同步

- 卡牌 ID / 效果 ID 重命名会同步更新目标表达式中的 `with_effect[...]`、公式中的 `effect[...]`、条件、分支条件和肉鸽配置中的引用。
- 一键迁移会给步骤写入公式字段，同时保留旧版字段，便于切回旧版检查。


### 伤害

```
基础值
→ 攻击方伤害提升百分比与提升值
→ 攻击方最终伤害提升百分比与提升值
→ 减去防御方对应属性抗性（真实伤害忽略）
→ 防御方受伤降低或提高
→ 向下限零取整
```

物理、精神、真实对应的跳字与动效颜色分别为 `#FF0000`、`#0000FF` 和 `#00FF00`。

附加伤害（`bonus: true`）先计算基础值，忽略攻击方伤害增益与最终伤害增益，也无视防御方抗性、减伤与受伤修正；它仍会触发致命保护与退场，但不作为一次新的攻击事件。

### 结算模型

战斗引擎同步执行，不使用并发写入战斗数据。伤害造成的生命归零先记录，等本次行动中的伤害、致命保护、退场触发和相关被动完成后再统一处理。主要步骤类型：

```
damage / heal / addEffect / removeEffect / modifyCount / readCount
branch / selectTarget / forEach / loop / castSkill / skipAction
immuneDamage / forceRetreat / summon / modifyStat / setVar
```

被动技由事件触发并检查 `trigger.event`、触发条件与释放条件。主动技只在自身行动时可用；附加技不占用行动。

## 抽牌模式与独立牌组

- **面对面对战**始终使用公共单位牌池抽牌，不读取牌组构筑。
- **自定义对战**可切换「允许战斗中抽牌」：
  - 开启：公共单位牌池模式，牌组构筑不参与本场对战。
  - 关闭：双方使用牌组构筑模块保存的红蓝独立牌组；默认牌组为双方各一只普通的史莱姆，但可以在独立牌组构筑中替换。
- 公共单位牌池按 **白 50% / 蓝 40% / 金 10%** 的品质权重抽取，只会抽到角色牌，不抽装备或符文。
- 开局双方各抽 `initialDraw` 张，场地为空；双方先在空位选择上场角色，至少各有一名计数角色后点击「开始战斗」。
- 每经过 `drawInterval` 回合，双方再各抽 `drawCount` 张。直到一方没有计数手牌且场上没有计数角色时失败。
- 关闭抽牌的自定义对战使用独立构筑的红蓝牌组；新存档的默认内容是红方普通的史莱姆 ×1、蓝方普通的史莱姆 ×1。

## 肉鸽配置数据

肉鸽的可调内容集中在 `data/rogue/config.json`：

- `startingGold`：起始金币。
- `battleRules`：肉鸽战斗的初始抽牌、场地上限等规则。
- `map.layers` / `map.nodeTitles`：每层节点类型与节点标题。
- `encounters.battle` / `encounters.elite` / `encounters.boss`：三类遭遇的敌人池、数量、装备、符文、属性修正、开局效果和品质/层级条件。
- `characterShop`：角色商店的卡数、刷新费用、品质权重和品质价格。
- `shop`：节点商店的商品类型、数量、品质权重、价格加成与固定价格。
- `loot`：战利品条目、选择数量、品质权重、保底装备与数值。
- `rest`：休整选项的文字、效果和数值。
- `battleGold`：战斗胜利的未溢出伤害转化金币比例。

商店品质权重均支持 `white / blue / gold / rainbow`，默认：

```json
{ "white": 50, "blue": 40, "gold": 10, "rainbow": 0 }
```

即默认不会出现彩色品质；把 `rainbow` 改成大于 0 即可启用。

扩展包可以在顶层增加 `rogueConfig` 对象覆盖默认配置。对象会递归合并，数组会整体替换：

```json
{
  "format": "caerogue.expansion",
  "id": "my.rogue.config",
  "name": "我的肉鸽规则扩展",
  "content": { "units": [], "skills": [], "effects": [], "equipment": [], "runes": [] },
  "rogueConfig": {
    "startingGold": 50,
    "characterShop": { "qualityWeights": { "white": 30, "blue": 50, "gold": 20, "rainbow": 0 } }
  }
}
```


## 肉鸽事件数据

默认事件在 `data/rogue/events.json`，直接修改后刷新即可；文件不存在或格式错误时会提示并使用兜底事件。事件结构：

```json
{
  "version": 1,
  "events": [
    {
      "id": "rogue.example",
      "title": "事件标题",
      "text": "事件描述",
      "weight": 1,
      "minLayer": 0,
      "maxLayer": 5,
      "choices": [
        { "text": "选项", "hint": "提示", "effect": "gold", "value": 10 }
      ]
    }
  ]
}
```

可选效果：`gold`、`hp`、`dmg`、`unit`、`equipment`、`rune`、`rewrite-shop`、`battle`。`id` 可用于指定固定角色/装备/符文；省略时随机选择。

扩展包可以在顶层加入 `rogueEvents` 数组，采用与普通扩展包相同的方式放进 `data/pack/` 并写入 `index.json`：

```json
{
  "format": "caerogue.expansion",
  "id": "my.rogue",
  "name": "我的肉鸽扩展",
  "content": { "units": [], "skills": [], "effects": [], "equipment": [], "runes": [] },
  "rogueEvents": [
    { "id": "my.event", "title": "新事件", "text": "……", "weight": 1, "choices": [{ "text": "拿钱", "hint": "+10", "effect": "gold", "value": 10 }] }
  ]
}
```

同 ID 的事件会覆盖默认事件；扩展包被禁用后，其中的事件也会一并移除。

扩展包也可以同时提供 `rogueConfig`，用于覆盖起始金币、商店权重、战利品、地图与遭遇等配置，加载方式与普通扩展包一致。


## 经济

- 肉鸽与无尽都以 **30 金币**起步，且没有初始自选角色/牌组。
- 常驻角色商店：5 张，白 50%、蓝 40%、金 10%；价格 5 / 10 / 15，刷新 10。
- 节点商店：角色/装备/符文按品质约 8 / 13 / 18；生命或伤害强化 20；移除角色 10。
- 肉鸽与无尽早战斗胜利时，获得等同于**本场对敌方造成的未溢出实际伤害**的金币；溢出伤害不计入。战利品兑换与事件金币约 10–15。
- 通用「诗篇祝福」类效果奖励已移除，角色专属效果不再作为全角色通用奖励出现。


「变量与目标」面板中的目标之一为「效果持有者」：默认指向当前效果来源；在步骤中选择该目标后，可在「指定效果」里选择效果，目标会变为场上所有携带该效果的单位。

## 编辑器

「编辑器」是唯一的卡牌创建与修改入口，包含五个标签页：

1. **角色**：名称、品质颜色、系列 / 特性、生命、攻击、抗性、生命上限限制、计数、自动行动、介绍、卡面资源与持有技能。
2. **技能**：触发、条件、目标、变量、分支、循环、召唤、强制退场、属性修改与步骤排序。
3. **效果**：层数、可解除性、数值修正、赋予技能与触发流程。
4. **装备**：武器 / 饰品、数值修正、赋予技能、介绍与卡面。
5. **符文**：适用系列、数值修正、赋予技能、介绍与卡面。

顶部可以选择编辑目标：草稿、默认卡包或任意已加载扩展。默认卡包和扩展内容可以直接修改；核心内容会保存为本地覆盖。草稿是独立包，创建后立即出现在卡牌库、牌组构筑与模式中，不需要先发布。

每个步骤块可单独切换旧版 / 公式模式。`selectTarget`、`readCount`、`setVar` 等可被目标表达式或数值公式替代的旧步骤已从选择器隐藏，只保留运行时解析。

「保存草稿」保存当前目标；「发布草稿」把草稿发布为本地扩展包，并清空草稿内容。编辑器还提供「包 ID」和「修改 ID」按钮：包 ID 变更会同步该包所有卡牌前缀，卡牌 ID 会强制使用 `包id_类型_自定义内容` 格式，并同步更新牌组、技能步骤、公式、挑战定义等引用。

自定义挑战可从挑战页的「创建自定义挑战」进入，配置 1–3 幕、敌方单位、生命/伤害修正和规则说明；自定义挑战保存在本地，可编辑或删除。

卡牌库现在只负责浏览和筛选，牌组构筑只负责调整卡组内容；角色创建弹窗已移除。

## 界面语言

所有界面中文文案都位于 `data/lan/zh_cn.json`，脚本中不再直接出现中文界面字符串，而是通过稳定的 `L('ui.…')` 键读取。`scripts/i18n.js` 在应用脚本执行前同步读取语言 JSON，因此模式名、状态标签、判定表和日志标签也能在初始化阶段完成本地化。设置页切换语言后会保存偏好并重载页面；默认语言为简体中文。

`data/lan/en_us.json` 提供英文界面；未翻译的条目会回退为中文。卡牌名称、技能名称和卡牌描述属于内容数据，保留在扩展包原文中。新增或修改界面文案后，可运行：

```bash
node tools/extract-locale.js
```

该工具会把脚本中残留的中文界面字面量提取为 `L('ui.…')` 键，并补充到两个语言文件；已有英文翻译会按原文自动复用。若修改脚本或样式后页面仍显示旧版本，请更新 `index.html` 中的 `?v=` 版本号或强制刷新浏览器缓存。

## 设计说明

- 装备与符文不进入抽牌堆，也不默认穿戴。
- 开局时双方自动组成初始场地。之后玩家一侧的空缺位置通过点击手动补牌；自动控制方自行补牌。
- 装备与符文只能在该方行动阶段调整。肉鸽与无尽的「战前整备」在战斗外配置并保留到后续战斗。
- 场上单位一般受场地上限约束；「区」的死亡召唤使用 `ignoreFieldLimit` 例外。
- 「区」会自动行动时，其他手动行动会被暂时阻止。
- 伤害动效使用全屏 Canvas 覆盖层；画布按当前单位的 `getBoundingClientRect()` 定位。
- 页面使用轻量 DOM 复用补丁更新，输入框焦点、选区和滚动位置在普通刷新中尽量保留。
- 扩展包分享码使用 UTF-8 JSON 的 Base64URL 编码，以 `CAE1.` 开头。工坊不依赖后端。

## 浏览器要求

建议使用支持 `backdrop-filter`、CSS 自定义属性、Canvas 2D、`fetch` 与 ES2020 的现代浏览器。项目内所有 SVG 插图与图标均为原创资产，未使用表情符号。
